# Kakuma ResourceLink — Architecture

> Connecting Opportunities, Inspiring Generations, Transforming Kakuma.

## A. System architecture & repository structure

```
                ┌───────────────────────┐        ┌──────────────────────┐
                │ Android (Kotlin/Compose)│       │ React + TypeScript    │
                │ Room cache · WorkManager│       │ SPA (Vite)            │
                └───────────┬────────────┘        └──────────┬───────────┘
                            │  HTTPS JSON  /api/v1/  (JWT Bearer)          │
                            └───────────────┬──────────────────────────────┘
                                            ▼
                        ┌──────────────────────────────────────┐
                        │ Django 5.2 + DRF (modular monolith)  │
                        │ accounts · opportunities · services  │
                        │ stories · diaspora · mentorship      │
                        │ contributions · notifications        │
                        │ moderation · ai_assistant ──────────┼──► Claude API (server-side key)
                        └───────────────┬──────────────────────┘
                                        ▼
                               PostgreSQL 16 (sole DB)
                               Media volume (uploads)
```

* One backend, one database, one auth system (Simple JWT) shared by both clients.
* No Firebase. The Claude API key lives only in backend env vars.
* Each Django app owns its models, serializers, services (business logic), permissions, views and tests. Views stay thin; rules live in `services.py`.

## B. Entity relationship design

All externally exposed IDs are UUIDs. All tables have `created_at`/`updated_at`.

```
User 1─1 Profile
User 1─0..1 AlumniProfile
User 1─* Opportunity (created_by, staff only)      User *─* Opportunity  via OpportunityBookmark
User 1─* Story (author)                             User *─* Story        via StoryLike / StoryBookmark
Story 1─* Comment *─1 User
User 1─* MentorshipRequest (as mentee) / (as mentor)
User 1─* CommunityProject (owner)   CommunityProject 1─* Contribution *─1 User
User 1─* Notification (recipient)
User 1─* AIConversation 1─* AIMessage
User 1─* Report (reporter) ──► generic target (story/comment/project)
User 1─* ModerationDecision (moderator) ──► generic target
```

| Entity | Key fields | Constraints / indexes |
|---|---|---|
| **User** | id, email (login), full_name, role {member, alumni, mentor, moderator, admin}, preferred_language {en,sw,es,it,de} | unique email (case-insensitive) |
| **Profile** | user, bio, location, avatar, phone (private) | 1-1 user |
| **Opportunity** | title, category {scholarship, education, vocational, job, internship, entrepreneurship}, organization, summary, description, requirements[], location, is_remote, deadline, application_url, language, status {draft, published, archived}, is_verified | idx (status, category), idx deadline |
| **OpportunityBookmark** | user, opportunity | unique (user, opportunity) |
| **Service** | name, category {healthcare, humanitarian, education, legal, protection, livelihood, community}, organization, description, phone, email, website, address, lat/lng, opening_hours, is_verified, last_verified_at, is_active | idx category |
| **Story** | author, title, slug, excerpt, body (Markdown), cover_image, category, language, status {draft, pending_review, published, rejected, archived}, consent_to_publish, rejection_reason, published_at, reading_time | idx (status, published_at), unique slug |
| **Comment** | story, author, body, is_hidden | idx (story, created_at) |
| **StoryLike / StoryBookmark** | user, story | unique (user, story) |
| **AlumniProfile** | user, country, city, profession, organization, skills[], bio, is_mentor, mentorship_areas[], willing_to_contribute, visibility {public, members, private}, show_contact_email, consent_given_at | 1-1 user, idx (visibility, is_mentor) |
| **MentorshipRequest** | mentee, mentor, goal, help_areas[], message, status {pending, accepted, declined, cancelled, completed}, response_message, responded_at | unique pending (mentee, mentor); check mentee ≠ mentor |
| **CommunityProject** | owner, title, summary, description, category, location, cover_image, status {pending_review, active, completed, rejected}, accepted_contribution_types[], funding_goal, currency | idx status |
| **Contribution** | project, contributor, type {mentoring, volunteering, equipment, skills, financial_pledge}, description, amount, currency, status {pledged, confirmed, fulfilled, cancelled} | amount required iff financial_pledge, check amount > 0 |
| **Notification** | recipient, type, title, body, data(json), is_read, read_at | idx (recipient, is_read, created_at) |
| **AIConversation** | user, title, language | idx (user, updated_at) |
| **AIMessage** | conversation, role {user, assistant}, content, model, input_tokens, output_tokens | idx (conversation, created_at) |
| **Report** | reporter, target (generic), reason, details, status {open, resolved, dismissed} | |
| **ModerationDecision** | moderator, target (generic), action {approve, reject, hide, restore}, note | |

**Financial pledges are intentions, not payments.** The platform processes no money; `status=pledged` is the default and the UI must say "pledged", never "paid/donated".

## D. Android dependency & module plan

Single Gradle app module, **package-by-feature** with strict layer folders. This keeps the 36-hour build reachable while still preserving the Clean Architecture boundaries. Each feature can be split into its own Gradle module later without changing code structure.

```
mobile/app/src/main/java/org/kakuma/resourcelink/
├── core/
│   ├── network/      Retrofit, OkHttp, AuthInterceptor, TokenAuthenticator (Mutex-guarded refresh), ApiError mapping
│   ├── database/     Room AppDatabase, DAOs, entities, migrations
│   ├── datastore/    UserPreferences (language, theme, onboarding)
│   ├── security/     EncryptedTokenStore (Android Keystore AES-GCM)
│   ├── designsystem/ Theme, colors, typography, KR components (buttons, cards, chips, fields, skeletons, states)
│   ├── ui/           UiEvent, UiEventHandler (Toast/Snackbar, de-duplicated), UiText (localized)
│   ├── notifications/ channels + rich notification builder
│   ├── work/         SyncWorker, PendingOperationWorker
│   └── common/       Result/AppError, dispatchers, connectivity observer
├── feature/<auth|home|opportunities|services|stories|alumni|mentorship|projects|assistant|notifications|profile>/
│   ├── data/         dto, api, mappers, RepositoryImpl, PagingSource/RemoteMediator
│   ├── domain/       models, Repository interface, use cases
│   └── presentation/ ViewModel (StateFlow UiState + Channel effects), Compose screens
└── navigation/       NavGraph, destinations, bottom bar
```

Version catalog (`mobile/gradle/libs.versions.toml`) covers: AGP, Kotlin + Compose compiler plugin, KSP, Core KTX, Activity Compose, Compose BOM, Material 3, Navigation Compose, Lifecycle (runtime/viewmodel compose), Coroutines, Hilt (+ navigation-compose, work), DataStore, Room (+ paging, ksp compiler), Retrofit + Moshi converter, OkHttp + logging, Moshi (+ codegen via KSP), Paging (runtime + compose), WorkManager, Coil, JUnit, MockK, Coroutines Test, Turbine, AndroidX Test, Compose UI Test. Exact versions are verified against the local Android Studio toolchain in Phase 3.
